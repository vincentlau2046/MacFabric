## 原则（贯穿全部工作项）

- **隔离**：沙箱（8998）开发/验证 → commit → tag → 生产只吃发布产物；
  生产配置（~/.inferfabric）只在用户裁决的迁移点上动，且动前备份。
- **端到端**：每项能力以真实请求验收（聊天 200 / 嵌入向量合理 / 包安装全阶段），
  不以"接口返回了"为完成标准。

## 裁决 2：用户扩展能力包（用户选择"一期全做"）

- 入口：`POST /admin/packs/custom {name, url, capability, sha256?}`；
  capability 首期限 **llm / vl / embedding**（llama.cpp 框架内）。
- 校验链（任一不过即失败，明确报错）：
  1. 下载：复用 HttpArtifactFetcher（Range 断点续传、32GB 上限、https→http 降级拒绝）
  2. **格式**：GGUF 魔数（b"GGUF"）
  3. **门禁**：policy 参数量/内存预算预检（与官方包同一公式）
  4. **框架可运行**：真拉起 llama.cpp 隔离健康检查试加载（复用
     runtime_prep.healthcheck_llama_cpp 逻辑）——加载不起来 = 不符合现有框架
  5. sha256 可选用户提供，提供即校验
- 通过后：注册为用户自定义包（`user_custom: true`，持久 registry
  packs/user_custom.json），catalog_payload 合并展示（App 能力包页可见、
  可一键卸载）；写受控 yaml（embedding 加 --embeddings）进统一架构。
- 卸载：复用既有 uninstall 链路（停进程 + 删 yaml + 删包文件）。

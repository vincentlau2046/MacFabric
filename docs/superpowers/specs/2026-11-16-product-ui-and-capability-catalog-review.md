> 日期：2026-11-16。状态：**产品方向已获六项裁决；补充裁决：调用 ID 同步硬切，无旧别名。**

## 1. 目标与边界

把“工程功能可调用”提升为“用户能理解、比较、安装、验证和管理的 Mac 产品”。

- 本地推理：已安装部署的本地能力运行视图，不是内部配置文件列表。
- 能力包：按能力分类的完整精选目录；用户看见模型名、类型、能力、安装条件和验证状态，可一键安装/卸载。
- 同底座支持的常用同类模型进入正式规划，不停留在每类一个演示模型。
- 用户扩展继续共用官方包的注册、资源门禁、安装、健康检查、卸载与状态体系，不另起通道。
- 显示名称与内部身份分离；用户已裁决公开调用 ID 同步硬切，池本地候选和现有 key scope 必须受控迁移，无旧路由别名；不重写内部生命周期键或不可变历史。
- 强隔离、真实语义端到端和原生 GUI 验收是发布条件，不是后续补项。
- 保留现有侧栏术语、原生 SwiftUI + AppKit、Apple Silicon 定位、默认 LLM/VL ≤4B（可在设置调）、保留内存唯一设置入口。

非目标：全 Swift 重写、用 WebView 替换原生界面、用同一引擎硬跑所有能力、审核前批量下载、重置鉴权/重建用户密钥、默默迁移或删除用户资产。

鉴权当前只读核验：生产 /admin/security/status 返回 active=true、policy=all、enforced=true、key_count=1；8999 仅监听127.0.0.1。**推理 API 鉴权已开启，未发现被关闭。** 不复制密钥记录或任何明文到本稿。

管理面与调用面必须分开表述：_check_admin 使用独立 X-Admin-Token；无管理令牌配置时依赖本机监听。API Key 开启并不等于所有 /admin 路由都受同一 Bearer key 保护。当前未带管理头可读取状态；不能把管理接口200称为推理鉴权失效，也不能称全接口均有鉴权。

## 3. 可选路线与推荐

| 路线 | 做法 | 局限/代价 |
|---|---|---|
| A 局部修饰 | 截断内部名称、减小徽章、固定若干 frame | 最快，但名称仍由 ID 猜，跨页数据继续分裂；不推荐 |
| **B 统一产品模型 + 表格/详情** | 后端统一提供展示元数据、状态与支持能力；原生共享列布局；详情收纳技术信息 | 已选；涉及数据契约与全页面清理，分阶段交付；公开调用ID按补充裁决硬切，需显式迁移闸门 |
| C 全界面/架构重写 | 新壳、新导航、新调用架构 | 回归面过大，与已有原生技术选择冲突；本轮不推荐 |

B路线已获批准；下文技术细节以正式v2合同为准。产品方向批准不等于已批准所有新实现接口或立即执行生产迁移。

## 4. 名称与信息模型规范

### 4.1 三层身份，禁止互相顶替

| 字段/概念 | 示例 | 展示位置与规则 |
|---|---|---|
| display_name（用户模型名） | BGE-M3；Qwen3-4B-Instruct-2507 | 所有列表标题、选择器、通知、确认弹窗统一使用；保留官方大小写与真实型号 |
| api_model_id（调用模型名） | bge-m3 等规范公开标识 | 只在接入配置/详情显示并可复制；显式注册，既有不规范调用名受控硬切，禁止内部名称回退 |
| 内部 model/pack ID、包版本 | pack-bge-m3-1-0-0 / embedding.bge-m3 / 1.0.0 | 排障详情；不得作默认标题或主徽章 |

模型名里的 4B、Instruct、2507 属于型号，不能误删；包版本1.0.0不是模型型号。多量化版本以变体列/副行区分，不把所有版本/格式拼成标题。显示名重复允许存在，行身份与操作依然绑定内部ID；同名不同变体必须明确区分。

不采用“前端去掉 pack- 再替换连字符”的长期方案。名称由 catalog/自定义注册元数据显式提供，安装后同步进入模型运行资料。旧配置通过审核后的迁移补元数据和规范公开调用ID，不重装权重；保留内部instance_id，迁移池/权限/缓存/示例，无旧ID别名。原本已规范且等于最终canonical的ID不错误退役。无法识别的历史型号显示诚实的回退名称与“资料待补全”，不得猜型号。

### 4.2 类型、能力、技术属性严格分层

- **类型**：文本生成、视觉理解、文本嵌入、相关性重排、语音识别、语音合成、文字识别、图像生成；文生图/图生图为图像生成的子能力。
- **能力标签**：例如中文、多语言、代码生成、工具调用、图像问答、语义检索、文档排序。最多主行2个，更多放详情；不把 GGUF/Metal/llama.cpp 当作用户能力。
- **技术属性**：参数量、量化、格式、实际配置上下文/模型理论上限、向量维度、引擎版本、许可、下载量、磁盘占用、内存需求，各自独立。
- **来源**：官方精选/用户添加；详情可追溯所属包与安装位置。
- **验证状态**：已验证/待验证/验证失败；**兼容性**独立为可安装/需适配/暂不支持/资源或策略不符，不能把“已验证”当兼容性枚举。二者与安装状态和运行状态都分开；“模型作者宣称支持工具”不等于“当前网关工具调用端到端已验证”。

新增元数据建议：display_name、publisher、family、variant、primary_type、capabilities（含证据/验证状态）、api_model_id、runtime_support、verification、resources、source。具体 schema 与兼容默认值留给批准后的实施计划确定。后端统一导出，SwiftUI 不再镜像硬编码模板可用白名单。

## 5. UI 规范：表格负责比较，详情负责解释

### 5.1 设计系统

沿用既有织物蓝与原生 SF Pro/PingFang SC，不另起风格。参考 PLAN §8：

- 浅色桌面 #F5F5F8、面板 #FFFFFF；深色桌面 #101014、面板 #17171C。
- 主强调浅色 #3D5CE5、深色 #5F7DFF；正文/次级/分隔优先采用可适配主题的原生语义色；成功/警告/失败采用系统语义色。
- 模型标题13–14pt semibold，正文13pt，次级信息11–12pt；路径、ID与数值才用等宽字体，数值使用等宽数字并右对齐。
- 间距4/8/12/16/24；窗口内容边距16；按钮使用统一原生控制尺寸。表格行建议52–60pt，标题单行；大字体模式允许自然增高，不能裁掉文字或焦点。
- 默认不做每行厚圆角卡片：一个表面容纳连续行，轻分隔与选择高亮；颜色只表达能力/状态，不用多层彩色描边争夺注意力。
- 浅/深色、键盘导航、VoiceOver、焦点态、减弱动态效果纳入验收；状态不能只靠红绿灯。

### 5.2 本地推理

建议默认主列：**模型名称｜类型｜能力｜运行状态｜内存｜操作**。

```text
本地推理                       [搜索模型] [类型：全部] [状态：全部]
模型名称                      类型       能力                状态      内存基线       操作
BGE-M3                       文本嵌入   多语言 / 语义检索    未加载      2.1 GiB      [加载] [⋯]
Qwen3-4B-Instruct-2507         文本生成   中文 / 对话          未加载      4.7 GiB      [加载] [⋯]
```

此处能力标签是目标版式例子，具体是否标为已验证以测试证据为准。

- 共享列宽而非每行独立自适应；类型/状态/资源/操作稳定对齐，资源右对齐，按钮位置固定。
- 首列优先分配剩余空间，长名称单行尾部截断+详情全文，不能通过压缩状态/按钮换空间；完整名称可复制。
- 随窗口变窄先收起次要能力列/资源细项到详情，保留名称、类型、状态、动作；不重新变为挤满标签的横排。
- 主列表不展示包ID/引擎端口/默认启动开关/长装载说明。选中行的详情检查器展示：完整型号、能力、引擎、加载策略、自动启动、空闲回收时间、内存基线与实测、安装位置、技术ID。
- 展示“未加载/加载中/可用/已睡眠/异常”，不把已安装但未运行渲染成安装失败；休眠保留与未加载的生命周期差别。
- 用“从内存卸载/自动回收”描述运行态，用“卸载能力包”描述删除部署资产，避免一个“卸载”两种含义。
- 每行一个主动作（加载/唤醒/测试）；停止、睡眠、查看包等在次级菜单或详情。高风险动作保留确认。
- 本地推理测试入口按类型分派：对话输入、图片问答、嵌入样本与维度、查询+文档排序、音频转写、语音试听、OCR；不是所有模型都放进试聊框。
- 不再硬编码空闲30min或系统保留8G，显示后端真实策略；核对预算/保留是否重复扣减，信息缺失显示“未知”而非0或编造端口。

### 5.3 能力包

结构：类型导航/筛选 + 分类表格 + 模型详情；保留用户已裁决“按能力分类”，不再用分类标题下面堆卡墙。

```text
能力包                       [搜索] [适配本机] [已验证] [添加模型链接]
类型：全部 / 文本生成 / 视觉理解 / 文本嵌入 / 相关性重排 / …

文本嵌入
模型名称                能力                   变体       下载 / 磁盘    兼容性     验证       安装状态     操作
BGE-M3                 多语言 / 语义检索       …          …              可安装     已验证     已安装      [管理] [⋯]
Qwen3-Embedding-0.6B    多语言 / 语义检索       待选定      未知           需适配     待验证     未安装      [查看]
```

- “全部”页保留分组表头；类型筛选后只展示对应类型；未支持分类可在“规划中”区域明确标记，不伪装可安装库存。
- 默认显示适配本机/政策允许的候选，可切换查看全部；超出设置限制/内存不足的条目不消失，明确给出原因，不擅自调整用户设置。
- 下载大小、安装占用、内存需求分清，未知不显示0；统一二进制资源单位MiB/GiB并注明估算/实测。
- 安装/进行中/取消或失败处理/重试/已安装/卸载/被池引用确认的状态文案一致；不支持取消时不显示假取消按钮。
- 正在安装显示阶段+实际进度（不知道总量时用不定进度）；失败显示可理解原因+修复动作，原始堆栈放详情。
- 详情展示完整安装预设路径与安装后真实路径，提供复制/在Finder中显示；路径不挤在主表格里。
- 相同模型多个量化变体收纳到模型详情选项；目录项、安装变体与运行实例的对应关系显式保留。

## 6. 能力与常用模型目录规划

**统一的是安装/注册/调用/资源/验证合同，不是所有类型强行使用一个引擎。** 同一个 llama.cpp 底座仍需文本、视觉、嵌入、重排不同模板，且必须核对固定版本的真实支持。

当前能力事实：有完整包路径与历史调用证据的是Qwen3-4B与BGE-M3 dense；bundled catalog的Kokoro/OCR仍是模板未实现的占位，VL和rerank没有当前可安装正式包。BGE-M3 dense成功不能宣传为已提供sparse/多向量“混合检索”。

沿用既有裁决：模型下载源以ModelScope为准；上游模型卡只作为元数据/许可参考，不作为默默切换下载源的授权。找不到合规、可达、摘要冻结的源就不晋级。Whisper此前因无对应ModelScope产物被移出，只能在源问题解决或用户明确复议后恢复；Gemma许可证复核前不进入任何交付批次。首批扩为12个目标已获批准；不覆盖既有源/许可限制，也不代表已验证支持。

### 6.1 首批精选目标（12个型号，候选不等于已支持）

引擎冻结策略建议：以现有llama.cpp b12361为回归基线，先核实各模板与目标模型支持；如果VL/重排等要求升级，先做完全隔离的兼容性小验证，产出确切tag/commit、arm64构建产物SHA256与既有两包回归结果，提交版本选择报告后再冻结新引擎。禁止随master漂移或直接替换生产运行时；旧包保留原运行时，升级可回退。批准候选清单不等于批准一个尚未选出的新引擎版本。

| 类型 | 型号目标 | 定位 | 上线条件 |
|---|---|---|---|
| 文本生成 | Qwen3-0.6B、Qwen3-1.7B | 低内存轻量对话 | 分别完成正式包、语义测试；不能把之前0.6B试装当已交付目录 |
| 文本生成 | Qwen3-4B-Instruct-2507 | 默认中文对话 | 沿用已装包，补显示资料与免重启/GUI/鉴权回归 |
| 文本生成 | Qwen2.5-Coder-1.5B、Qwen2.5-Coder-3B | 代码任务 | 两个型号分别固化来源、模板、可用量化与测试 |
| 文本生成 | LFM2-2.6B | 非Qwen轻量备选 | 固定引擎架构支持、许可证、Mac实测；不通过不入可安装区 |
| 文本嵌入 | BGE-M3 | 多语言检索 | 已有1024维取证需补语义排序/批量/重启/端点回归 |
| 文本嵌入 | BGE-small-zh-v1.5 | 轻量中文检索 | 确认GGUF转换、pooling、归一化、向量维度与查询格式 |

以上12个型号采用按类型分批晋级，不批量挂“已验证”。首轮只选每型一个推荐量化变体（文本通常从Q4_K_M评估；嵌入/重排不照抄生成模型量化，需质量实测），不同时膨胀为几十个文件变体。所有大小、许可、峰值、上下文、镜像来源在模型条目确认阶段逐一核实，不在本稿编造。

## 7. 用户扩展：从“填链接”到可被信任的模型条目

目标入口以下载链接为主；型号/类型从仓库元数据和GGUF元信息尽量识别。显示名可编辑，内部slug自动生成；不要求用户理解pack命名。能力识别不确定时才要求确认；不可假装万能自动识别。

推荐流程：粘贴链接 → 安全解析/元信息检查 → 展示识别结果和缺失依赖 → 资源预检 → 用户确认 → 隔离下载/校验/能力测试 → 正式注册 → 分类列表出现。

- HTTPS与重定向目的地检查、私网/本机/元数据地址默认拦截、下载上限/解压路径/超时/磁盘预检、可选摘要校验；用户模型不自动执行远端脚本。
- 下载前可用Content-Length/元数据做初检，缺失时按保守策略和流式限额；不能等下完大文件才发现超资源。
- GGUF魔数只证明格式开头，不证明类型、参数量、能力或安全；读取元信息并与声明交叉验证。
- LLM/VL参数量门禁遵循设置，不以文件体积粗估冒充真实参数量；未知时明示不能完成预检，不绕过。
- VL补齐匹配投影文件；Embedding/重排有专用模板；不适配的类型拒绝并解释。
- 引擎运行时由独立、版本固定、可校验的托管依赖提供，不依赖“先装一个官方模型”或跨包runtime符号链接；卸载任何模型不能拖垮另一个模型。
- 官方/自定义两条入口共用安装事务、资源门禁、状态机、配置落盘、注册重载与卸载。失败可重试/移除，取消与重启后可恢复；不产生平行registry与假installed。
- 健康检查不仅/health 200，必须按类型执行真实能力样本；通过后才宣告可用。鉴于这是用户提供的模型，明确其来源未获官方质量背书。

## 8. 鉴权与接入规范

1. 保持现有policy=all与用户密钥不变，先修显示与调用链；绝不为了试聊方便关闭鉴权。
2. 接入页、设置页、首启与试聊使用同一类型化状态：检查中 / 已启用（全部推理请求）/ 仅模型池 / 未启用 / 无法连接。未知不渲染成未启用，旧状态标明更新失败。
3. 单独显示“推理调用鉴权”和“本机管理权限”；管理令牌硬化方案单列安全子任务，不悄悄把Bearer推理key当管理员凭证。
4. 已启用时复制示例包含Authorization头或环境变量占位符，不带任何现存密钥明文。配置必须按模型类型选择端点，不给BGE-M3生成聊天示例。
5. App测试请求不免鉴权：建议用户一次录入现有网关key，存macOS Keychain（可选仅本次会话）；不通过读取摘要反推、不静默新建key、不把key写入源码/日志/复制示例。
6. UI明确“网关API Key”与“云服务商API Key”的区别。被撤销/过期/范围不允许分别提示，不笼统让用户去装模型。
7. 管理面硬化建议：独立本机管理凭证与Keychain传递，校验Origin/Host、限制浏览器来源和错误CORS；变更时需兼容App、launchd与CLI并另过安全审查。局域网功能继续保持未开启，不扩大监听范围。

## 9. 隔离、验证与发布门禁

### 9.1 首先修隔离

- 区分两层隔离：开发/生产资产隔离，以及用户模型引擎进程的执行隔离；独立进程组、SBPL符号可用、manifest声明均不足以证明后者成立。
- 引擎健康检查与正式启动都限定loopback、移除不必要的云端密钥等继承环境、约束可写目录与网络；OS沙箱采用实测有效的机制，无法强制实施时如实标注降级并按既有准入政策处理，不能写false伪装完整隔离。NOFILE/NPROC/CPU限制与并发上限需真实接入；macOS不可靠的内存rlimit不能冒充硬保证，采用资源预检、实测监测与失败清理。
- 开发环境的state、packs目录及state/policy/custom registry、models.d、池/云配置、日志、引擎依赖与端口均独立。
- 不允许可写目录或可写配置通过符号链接/硬链接指向生产；仅显式设计的不可变内容缓存可复用，并确保不可因卸载删掉共享依赖。
- 启动前解析realpath检查全部写目标；若指向生产立即失败，不接受“开发人员记住不要卸载”。
- 普通mock测试不使用生产凭证；外部真实模型/服务测试需显式启用，预算、停止与超时有真实终态监视。
- 对照测试前后生产文件摘要/进程与配置，证明安装失败、取消、重试和卸载未穿透生产。

### 9.2 真实验收，而不是全是200

| 门禁 | 证明内容 |
|---|---|
| 数据契约 | 同一模型全页面同名；显示名与公开ID显式分离，本轮公开ID按预览硬切；同名变体不串操作；退役ID含旧缓存不得路由；未知字段诚实回退 |
| 原生GUI | 最小/标准/大窗口、长中英文名称、30+条目、无模型/加载/失败、亮暗主题与键盘；共享列对齐；实际截图审核 |
| 鉴权 | 不带/错误/撤销/权限不符key被拒；合法key成功；UI展示与后端一致；复制配置及App试用真的可运行 |
| 文本 | 非空有意义正文、流式终态、按声明测试代码/工具；只有reasoning或空正文不算对话完成 |
| 视觉 | 真实图片相关回答；缺投影明确拒绝；不能用纯文本问答冒充看图支持 |
| 嵌入 | 维度、归一化、批量、相似度排序基本正确；返回1024个数只是必要非充分条件 |
| 重排 | 文档索引映射、排序与分数真实合理；返回200但乱序不通过 |
| 安装事务 | 安装后无需重启立即可调用；正式目录与自定义两链分别覆盖；失败/卸载后零受控残留；引用依赖不误删 |
| 重启恢复 | App/网关重启后状态、目录、能力、密钥状态一致，无假installed |
| 发布 | 网关与App都从同一已验证发布产物安装；不能只让网关走发布、App继续源码build直拷 |

资源数字与能力标签必须有来源；未测峰值展示估算，理论上下文不得冒充当前配置。测试输出有告警须记录，不写“无告警全绿”。

### 9.3 分阶段交付建议

- **阶段0：产品合同与安全底线**。本稿审核、信息字典/状态/设计令牌落基线；先给本地推理/能力包/模型服务三张静态视觉样稿（含长名称和窄窗状态），用户确认后才进入界面代码；强隔离、现有鉴权误显与试聊链路纳入必须项；修复安装热加载完整路径与契约测试。
- **阶段1：统一UI与现有两包**。元数据贯通、全页名称规范、表格/详情、真实资源策略与按类型接入；用现有BGE/Qwen先验证完整体验，不先堆模型。
- **阶段2：llama.cpp四类模板与首批12个精选型号**。文本→嵌入→重排→视觉分批；一个型号一套确切产物与测试证据，不通过不晋级。
- **阶段3：链接扩展正式化**。统一事务/依赖、自动元信息、安全与资源预检、按能力验证、失败恢复。
- **阶段4：其他常用能力逐类接入**。OCR、ASR、TTS、图像生成；仍遵循同一管理合同，明确新底座工作量。
- **阶段5：整版原生验收与发布**。真实GUI截图签收、能力语义矩阵、鉴权与隔离回归；发布产物双端一致、备份与回滚实测后晋升。

每阶段都可单独验收，但不得把阶段1宣告为阶段2–4已经可用；不在审核前承诺耗时或自动批量下载。
